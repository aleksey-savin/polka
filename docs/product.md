# Polka (Полка) — продуктовая спецификация

Актуально на 16 августа 2026. MVP (M0–M12) закрыт и работает; ниже — как разделы, описывающие исходный объём, так и последующие этапы (M13–M23): авторы и эталонный каталог, циклы, списки, сканирование пачкой, роли с модерацией, почта, тёмная тема.

## Что это и зачем

Polka — веб-приложение для ведения домашней библиотеки **бумажных** книг (в основном на русском языке). Главная боль владельца: книжные завалы, которые нужно разобрать, и отсутствие удобного инструмента для этого. Существующие сервисы либо про электронное чтение, либо неудобны для учёта физических книг.

Масштаб: личное пользование — владелец + пара друзей. Это осознанное ограничение MVP, а не временное упущение.

Форм-фактор: современное веб-приложение, mobile-first (основной сценарий разбора завалов — с телефоном в руках у полки), устанавливается на домашний экран (PWA-manifest). Задел на кроссплатформу (позже возможен Capacitor).

## Роли

| Роль                 | Кто это                                                 | Что может                                                                                                                      |
| -------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Участник библиотеки  | Зарегистрированный пользователь, состоящий в библиотеке | Всё внутри неё: книги, полки, выдачи, ссылки, заявки. У библиотеки может быть **несколько совладельцев** (семейная библиотека) |
| Создатель библиотеки | Участник-основатель                                     | То же + приглашает/удаляет участников, может удалить библиотеку                                                                |
| Гость                | Человек со секретной ссылкой, без аккаунта              | Смотреть расшаренную библиотеку/полку; отправить заявку «хочу взять почитать» (имя + записка)                                  |

Аккаунты друзей с их оценками/комментами — фаза 2.

**Регистрация — по приглашению.** Пустая система: первый пользователь регистрируется свободно. Дальше единственный способ создать аккаунт — одноразовая ссылка-приглашение `/join/<токен>` (живёт 7 дней), которую генерирует любой зарегистрированный («Друзья» → «Пригласить в Полку»). Никаких флагов окружения.

## Структура каталога

- **Библиотека** — физическое место (дом, дача, кабинет). У пользователя их может быть несколько. **Совладение**: в библиотеке может состоять несколько пользователей (муж и жена ведут один «Дом», книги не делятся по аккаунтам). Приглашение — инвайт-ссылкой: залогиненный человек открывает её и становится участником. Все участники полноправны в каталоге; создатель дополнительно управляет составом участников.
- **Полка** — внутри библиотеки, упорядочены вручную. У полки может быть **акцентный цвет** (см. «Живые полки» в ux-ui-guideline).
- **Книга** стоит ровно на одной полке **или** лежит в «Неразобранном» своей библиотеки (инбокс для разбора завалов).
- **Серия** — самостоятельная сущность для группировки книг: издательская серия («Чёрная кошка») или авторский цикл (детективы про одного сыщика). Серия глобальна для пользователя — её книги могут стоять на разных полках и в разных библиотеках. У книги не более одной серии + номер тома (свободный текст: «3», «3.5», «3–4»); вторичные группировки — тэгами.
- **Тэги** — свободные метки пользователя (жанры, «подарить маме», что угодно). Книга ↔ тэги: многие-ко-многим.

## Карточка книги

Поля: название*, авторы (текстом: «Фамилия Имя; Фамилия Имя»), ISBN-10, ISBN-13, издательство, год издания, серия + № тома, число страниц, язык (по умолчанию `ru`), аннотация, обложка (файл: загрузка или скачивание из найденных метаданных), приватные заметки владельца, тэги.

### Статус владения (ровно один)

| Статус       | Смысл                   | Поведение                                                                                                                   |
| ------------ | ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `in_library` | Стоит дома              | Видна на полке/в «Неразобранном»                                                                                            |
| `wishlist`   | «Хочу» — ещё не куплена | Личный список `/wishlist` каждого пользователя, без библиотеки/полки; после покупки назначается полка и статус `in_library` |
| `gifted`     | Подарена (кому + когда) | Уходит с видов полок; находится фильтром в каталоге                                                                         |
| `lost`       | Потеряна                | Аналогично `gifted`                                                                                                         |

Принцип: **полка отражает физическую реальность** — чего нет в доме, того нет на полке.

### «На руках» (выдачи)

«Дал почитать» — не статус владения, а **журнал выдач**: кому (имя текстом), когда, срок (опционально), записка, дата возврата. Активная выдача (без даты возврата) — максимум одна на книгу; книга при этом остаётся на полке визуально, но помечена штампом «НА РУКАХ». Страница `/loans`: активные выдачи + история. История выдач видна и на карточке книги.

### Чтение и оценка — личные у каждого участника

- Статус чтения: `unread` / `reading` / `read` / `abandoned` + дата прочтения.
- Оценка 1–5 (звёзды) и рецензия (свободный текст).
- Приватные заметки.

В общей библиотеке эти поля у каждого участника **свои**: муж и жена читают и оценивают одну книгу независимо. Карточка показывает оценки всех участников («Алексей ★5 · Оля ★4») и рецензии рядом; заметки видны только автору. Общие у книги: библиографические поля, полка, тэги, выдачи, статус владения.

## Добавление книг

Три равноправных пути, оптимизированных под «стопку книг на полу»:

1. **Сканер штрихкода** камерой телефона (EAN-13 → ISBN) — основной для массового ввода.
2. **Ввод ISBN** вручную (13 или 10 цифр, с дефисами или без).
3. **Полностью вручную** — форма с нуля.

После скана/ввода ISBN приложение ищет метаданные в интернете (Google Books + OpenLibrary + FantLab, см. architecture.md) и показывает **черновик карточки**, который пользователь правит и подтверждает. Найденное название серии предзаполняет выбор серии (создастся при сохранении, если новой).

**Честное ожидание:** для современных русских ISBN автозаполнение срабатывает примерно в 40–70% случаев, для книг 90-х — хуже. Поэтому ручная форма — первоклассный сценарий, а «ничего не нашлось» мгновенно превращается в ручную форму с уже заполненным ISBN. UX обязан оставаться приятным при 0% попаданий.

Поток «разбор завала»: сохранил книгу → кнопка «Добавить ещё» возвращает сразу к сканеру; выбранные библиотека/полка (или «Неразобранное») — липкие между добавлениями. При совпадении ISBN-13 с существующей книгой — предупреждение о дубле (дубль сохранить можно: бывают два экземпляра).

## Каталог и поиск

Раздел «Каталог» — глобальный поиск с фильтрами. Строка поиска: название, авторы, название серии — регистронезависимо **для кириллицы**. Полнотекстовый поиск (FTS5) — после MVP.

**Фильтры (M10, макет `docs/design/catalog-v2.html`).** На мобильном — кнопка «Фильтры» со счётчиком активных, открывает шторку; применённые фильтры видны чипами с крестиками прямо на странице. Именование: «**Где книга**» — местонахождение (дома / на руках / хочу / подарены / потеряны / скрытые), «**Статус чтения**» — не читал / читаю / прочитал / бросил. Секции шторки: где книга, библиотека и полка, статус чтения, **автор** (ввод + частые авторы чипами), **период издания** (от–до + пресеты), серия, тэги. Отдельной сущности «жанр» нет — жанры ведём тэгами; настоящие жанры из метаданных — кандидат в v2. Кнопка шторки показывает живой счётчик: «Показать N книг». На десктопе фильтры остаются строкой селектов.

Два скоупа поиска:

- **Мои книги** — весь свой каталог.
- **У друзей** — поиск по сохранённым чужим полкам (см. «Полки друзей» ниже). В результатах видно, у кого книга и свободна ли она; отсюда же заявка «Хочу почитать» в один клик (имя подставляется из профиля).

## Шэринг и заявки

- Владелец создаёт **секретную ссылку** на библиотеку или полку (`/s/<токен>`). Ссылку можно отозвать.
- Гость по ссылке видит read-only витрину: книги с обложками, авторами, годом, серией, аннотацией и статусом «на руках/свободна». **Не видны**: приватные заметки, имена должников, статусы чтения, оценки и рецензии — наружу отдаётся явный белый список полей.
- На карточке книги гость может отправить заявку **«Хочу взять почитать»**: имя + записка (без регистрации).
- Владелец видит заявки в инбоксе `/requests` (бейдж в навигации) и либо отклоняет, либо **одобряет — заявка превращается в выдачу** с предзаполненным именем.

### Раздел «Друзья»

Отдельный раздел в навигации, две вкладки:

**Полки друзей** (входящие). Залогиненный пользователь, открыв чужую share-ссылку, может **сохранить её себе**. Сохранённые полки/библиотеки видны карточками (чья, название, сколько книг), открываются в витрину; можно убрать. Отозванная владельцем ссылка пропадает сама. После сохранения:

- в Каталоге появляется скоуп «У друзей» — поиск по всем сохранённым полкам сразу (публичные поля, как на витрине);
- заявка «Хочу почитать» отправляется в один клик от имени профиля.

**Мои ссылки** (исходящие). Управление своим шэрингом: создать ссылку на библиотеку/полку, скопировать, отозвать; видно, сколько заявок пришло по каждой.

Аккаунтов-«друзей» и подписок в MVP по-прежнему нет — всё держится на ссылках.

## Раздел «Чтение» (личный хаб)

**Зачем.** Мобильная навигация упирается в пять слотов таббара: «Хочу», «Серии» и «Заявки» с телефона недостижимы, а вкладка «На руках» занимает целый слот ради редких заходов. «Чтение» — личная приборная панель читателя: не «найти книгу» (это Каталог), а «что у меня сейчас происходит». Каталог отвечает на запрос, «Моё» показывает состояния; его секции — быстрые входы в полные списки, данные не дублируются.

**Навигация после изменения.**

- Мобильный таббар: Библиотека · Каталог · [+] · **Чтение** (иконка-закладка) · Друзья.
- Десктоп-меню: Библиотека · Каталог · Серии · **Чтение** · Друзья · Заявки («Хочу» и «На руках» уходят внутрь «Чтения»).
- `/loans` и `/wishlist` остаются полными страницами — в них ведут секции «Чтения».
- Плавающая кнопка «+» остаётся приподнятой (это фича), но контент страниц получает нижний отступ, чтобы она ничего не перекрывала.
- В фильтр статуса Каталога добавляется пункт **«На руках»** — выданные книги находятся и поиском.
- Кнопка «+» — единственная постоянная точка добавления. Контекстные кнопки «Добавить» на страницах библиотеки/полки/каталога убираются как дубли; остаются только в пустых состояниях, где приглашают к первому действию.

**Секции страницы `/reading`** (сверху вниз; пустые секции скрываются целиком):

1. **Читаю сейчас** — книги с моим статусом чтения «читаю»: крупные обложки на полочной линии, под ними название, автор и «с {дата}». Тап — карточка книги.
2. **На руках · N** — активные выдачи: мини-обложка, название, «у «Имя»» с датой (просрочка подсвечивается), кнопка «Вернули» прямо в строке. Ссылка «Вся история →» на `/loans`.
3. **Хочу · N** — первые книги виш-листа (название, автор), ссылка «Весь список →» на `/wishlist`. Сценарий: быстро свериться в магазине.
4. **Прочитано в {год}** — счётчик книг за календарный год и средняя оценка; ссылка в Каталог с фильтром «прочитанные».

**Данные.** Одна серверная функция `getReadingHubFn` собирает всё за один запрос страницы: читаемые книги (личный слой текущего пользователя), активные выдачи по моим библиотекам, головка виш-листа + счётчик, счётчик прочитанного за год. Всё в рамках членства в библиотеках (`assertMember`), как везде.

**Пустое состояние всей страницы** (новый пользователь): подсказки-приглашения «Отметьте на карточке книги „Читаю“», «Добавьте первую книгу в „Хочу“».

**Открытый вопрос (решает владелец).** «В планах» как отдельный статус чтения (книга дома, хочу прочитать — не то же самое, что виш-лист «хочу купить») в MVP не вводим; если окажется нужным — добавим статус в личный слой позже.

## Разбор книг на мобильном

Массовое перемещение (раскладка «Неразобранного» по полкам) с телефона сейчас неудобно: мелкие чекбоксы, модальный диалог с дефолтом «первая библиотека по списку», после перемещения пользователь остаётся в отфильтрованном каталоге.

**Решения.**

1. **Отдельная страница «Разбор» (`/unsorted`).** «Разобрать стопку» из библиотеки ведёт на чистый список неразобранных книг — без фильтров и поиска, весь список сразу в режиме выбора: тап по карточке отмечает книгу с первого касания. В каталоге и на полке массовый выбор тоже есть (первый тап — по крупному чекбоксу, дальше тап по карточке; поиск и фильтры на время выбора прячутся).
2. **Панель выбора занимает место таббара** (как в нативных приложениях, ничего не перекрывает): «N кн.» · кнопка «Переместить» · круглая «✕».
3. **Шторки вместо диалогов.** На мобильном все модальные окна приложения открываются нижними шторками (ручка, скругление сверху, safe-area); на десктопе остаются центрированные диалоги. Реализация — адаптив в базовом Dialog, без переписывания вызовов.
4. **Умная шторка перемещения**: библиотека предвыбрана по выбранным книгам (общая библиотека выделения, а не первая по списку); полки — вертикальный список радио-строк (тап выбирает), «Неразобранное» первой строкой. Внизу списка — «+ Новая полка»: имя вводится тут же, полка создаётся и сразу выбирается — без возврата в другие меню.
5. **После перемещения**: если в текущем списке остались книги — остаёмся разбирать дальше; если список опустел — переходим на целевую полку.

## Скрытые книги

Иногда книгу не хочется показывать гостям: она стоит на полке, но на витринах ей делать нечего.

**Правила видимости.**

- «Скрыть» — свойство книги (`hidden`), переключают участники библиотеки; **все совладельцы видят скрытые книги** как обычно (это приватность от гостей, не от семьи).
- Скрытая книга **не попадает**: на публичные витрины `/s/<токен>` (и в их счётчики), в поиск «У друзей» у тех, кто сохранил ссылку, в гостевые заявки (сервер отклоняет заявку на скрытую книгу), в публичную раздачу обложек (`/api/covers` для гостей).
- На своих полках и в каталоге книга стоит как обычно — она физически дома.

**Индикация и управление.**

- В списках (каталог, полка, «Чтение») — значок перечёркнутого глаза в строке метаданных.
- На карточке книги — чип «Скрыта» под строкой издания; в меню «Ещё» — пункт «Скрыть» / «Не скрывать»; тост поясняет: «видна только владельцам библиотеки».
- В фильтре статуса каталога — пункт «Скрытые», чтобы найти все разом.

## Реалистичные корешки (полка как место поиска книги)

Задача — чтобы полку в приложении можно было визуально сопоставить с физической: нашёл глазами дома → нашёл в приложении. Цвет уже есть (акцент обложки); добавляем честные размеры и вид переплёта.

**Данные книги (новые поля).**

- `coverType` — переплёт: `soft` (мягкая обложка) / `hard` (твёрдый переплёт) / `gift` (подарочное издание); null = неизвестно.
- `heightMm` — высота книги в миллиметрах; null = неизвестно.
- Источники: **FantLab** отдаёт `format_mm` («145x215» → высота 215) и `cover_type» («твёрдая»/«мягкая») — заполняем при добавлении по ISBN; вручную — в форме книги (селект переплёта + высота в мм). **Сам ISBN физических размеров не кодирует** (префикс GS1 · группа · издатель · номер · контроль) — проверено, размер берём только из метаданных и рук.

**Геометрия корешка (единая для полки и стопки).**

- Толщина: непрерывно от страниц — `14 + страницы/14` px, зажато 18–56 (было 5 ступеней).
- Высота: `мм × 0.62` px, зажато 96–168. Фолбэк без мм — по переплёту (мягкая ≈118, твёрдая ≈138, подарочное ≈152), дальше — детерминированная вариация от названия, как сейчас.
- Вид: **мягкая** — плоский корешок со скруглением и лёгким бликом; **твёрдая** — кант (крышки чуть выступают сверху и снизу); **подарочное** — кант + золотое тиснение текста и ляссе (ленточка-закладка снизу).
- **Стопка «Неразобранное»** — те же книги лёжа: высота плашки = толщина корешка, длина = высота книги. Одна и та же книга выглядит одинаково на полке и в стопке.

**Сопутствующее.** Иконка вкладки «Библиотека» — стеллаж (`Library`) вместо домика; наклонённые корешки («на руках») больше не обрезаются сверху (запас в контейнере полки).

### Страница полки (M10)

Макет `docs/design/shelf-page-v2.html`. Решения: **медианный год удаляется отовсюду** (легенда патины была шумом — сам цвет полки остаётся); выбор цвета полки уходит с глаз — пункт «Цвет полки» в меню «Ещё» (шторка с авто-патиной, 8 пресетами и своим цветом); «Переименовать» и «Удалить» — тоже в «Ещё» (ActionMenu по гайдлайну, удаление — сургучом за разделителем). В шапке остаются: крошки, название, счётчик книг и одна кнопка «Ещё».

### Страница «Друзья» (M10)

Макет `docs/design/friends-v2.html`. Решения: **лента заявок** наверху страницы — мобильный вход в `/requests` (с таббара его не было), с именами и книгами, только при ожидающих заявках; вкладки — сегмент-пилюли со счётчиками; карточка полки друга — с **мини-полкой в патине владельца**; «Мои ссылки» — карточка со штампиком типа, метой (просмотры/заявки/дата) и кнопкой «Скопировать», «Отозвать» — в «Ещё» сургучом; создание ссылки — призрачная карточка «+ Поделиться…» → шторка с радио-выбором цели (библиотеки и полки) и CTA, называющим цель.

### Форма книги (M10)

Макет `docs/design/book-form-v2.html`. Решения: **поле «Высота, мм» убрано** (никто не измеряет книги линейкой — высота корешка заполняется только из FantLab, фолбэк — переплёт); **переплёт — чипы** с именованиями книжных магазинов («Не знаю / Мягкая обложка / Твёрдый переплёт»; интегральный из FantLab маппится в мягкую); **«Подарочное издание» — отдельный переключатель** (тип издания, не переплёт): на корешке отражается только габаритами по умолчанию (выше и толще), декор с золотом и ляссе убирается; в данных `coverType: soft|hard` + `giftEdition: boolean` (существующие `gift` мигрируют в `hard + giftEdition`); все поля ≥48px со шрифтом 16px (iOS не зумит), цифровые — mono с числовой клавиатурой; «Хочу» — строка-переключатель; кнопки сохранения — **липкая панель снизу** (primary «Сохранить и добавить ещё» + «···» с остальными вариантами), чтобы не скроллить длинную форму.

## Свой каталог-эталон и авторы (план M13–M15)

Цель — независимость от внешних сервисов: свой справочный слой данных, который наполняется из API один раз, а дальше живёт у нас. Пользовательские записи — всегда копии; эталон неизменяем; поиск метаданных — только по эталону.

### M13 — Сущность «Автор»

- Таблицы: `author` (id, name, nameNorm, fantlabId nullable, openlibraryId nullable, `bio`, `birthYear`, `deathYear`, `country`, `photoPath` — все nullable, заполняются фоном в M15; createdAt; дедуп по nameNorm) и `book_author` (bookId, authorId, position — порядок соавторов). FantLab по автору всегда отдаёт даты жизни/страну/фото, биографию — в основном у фантастов; OpenLibrary дополняет bio. Фото одно на автора — скачиваем при обогащении.
- Строка `book.authors` остаётся денормализованным отображением (карточки, корешки, формы не меняются); сервер синхронизирует связки при создании/правке книги.
- Миграция существующих книг: разрез строк по «;», дедуп, связки.
- FantLab при lookup отдаёт `[autor=14093]…[/autor]` — кладём `fantlabId` сразу.
- Страница автора `/authors/$id`: его книги на моих полках; имена авторов в карточке книги становятся ссылками.
- Фильтр и фасет «Автор» в каталоге переезжают с LIKE-эвристик на таблицу.
- Ролей (переводчик, составитель) сознательно нет.

### M14 — Эталонный каталог: произведения и издания

Модель двух уровней (как у FantLab и OpenLibrary):

- **`ref_work` — произведение** («Заповедник», 1983, аннотация): source+sourceId unique, title/titleNorm, year, annotation; связка `ref_work_author`.
- **`ref_book` — издание** (ISBN, издательство, год, страницы, переплёт, обложка): source+sourceRef unique, isbn13 индекс, rawJson, fetchedAt; связки `ref_book_author` и **`ref_book_work` (M:N)** — сборник содержит несколько произведений, произведение живёт во многих изданиях.
- **Неизменяемость**: пользователь эталон не редактирует; обновление — только повторным фетчем.
- **Естественное наполнение**: обычное добавление книги по ISBN сохраняет в эталон и издание, и его произведения (FantLab отдаёт состав сборника со ссылками /work; авторы произведений — через ensureAuthor). База растёт от использования.
- Порядок lookup: **сначала свой эталон по ISBN** (вечный, без TTL), при промахе — внешние API с сохранением ответов в эталон; `lookup_cache` остаётся сетевым кэшем и постепенно уйдёт.
- `book.refBookId` — связь экземпляра с изданием эталона. Правки пользователя живут в `book`, в матчинге не участвуют.
- **Библиография на странице автора** — список произведений (не изданий!) с годами; пометка «есть» — через покрытие: сборник «Малое собрание сочинений» закрывает все пять входящих произведений (связь book → ref_book → works + fallback по названию для старых книг). Кнопка «В Хочу» на произведении — быстрое желание без ISBN. **Шторка произведения** (макет `docs/design/work-editions.html`): тап по строке библиографии → аннотация + список изданий (обложка, издательство, год, страницы, переплёт); «есть» на издании — точный ISBN-матч; «В «Хочу»» на конкретном издании — со всеми его данными; внизу — «В «Хочу» без выбора издания». Издания грузятся лениво при первом открытии с сохранением в эталон.

### M15 — Фоновое наполнение (библиография авторов)

- Очередь: `crawl_task` (kind='author-bibliography', authorId, status, attempts, scheduledAt) + фоновый воркер в server.ts: медленный цикл с паузами и джиттером (FantLab в test-режиме — щадящий rate limit), env-флаг `CRAWL_ENABLED`.
- Триггеры: появление автора с fantlabId → задача; повторное обновление — не чаще раза в N месяцев; ручная кнопка «Обновить» на странице автора.
- Источники — все три, по задаче на пару (автор, источник): FantLab `/autor/{id}` (по fantlabId), OpenLibrary `/authors/{olid}/works` (по openlibraryId), Google Books `inauthor:"…"&langRestrict=ru` (по имени, с ключом). Фоном тянем **только библиографию (произведения)** — 1–2 запроса на автора; **издания произведения — лениво**, при первом раскрытии на странице автора, с кэшем в эталон. Только русскоязычные, только авторы моих книг. Дедуп — по ISBN/sourceId, приоритет FantLab.
- UI: на странице автора секция «Другие книги автора» из эталона (с пометкой даты обновления); кнопка **«В «Хочу»»** — один тап: книга создаётся в виш-листе со всеми данными эталона и скачанной обложкой; имеющиеся издания помечены «есть» (по ISBN).

### Риски и правила

- FantLab API — «test mode»: воркер обязан переживать ошибки/пустые ответы и не долбить сервис (глобальный интервал между запросами, ретраи с бэкофом).
- Дедупликация эталона между источниками — по ISBN; при конфликте приоритет FantLab (как в merge).
- Объём: у плодовитых авторов сотни изданий — лимит на задачу + только издания с ISBN.
- ИИ-механики поверх эталона (обогащение, рекомендации) — отдельный этап после M15.

## Циклы произведений (M16)

Решение владельца — не смешивать сущности:

1. **Издательская серия** — остаётся отдельной сущностью и хранит только издательские данные («Ю Несбё (новое оформление)»). В форме книги поле переименовывается в **«Издательская серия»**.
2. **Циклы вычисляются отдельно** из эталона: FantLab `cycles_blocks` → циклы как `ref_work` с типом cycle + связка `ref_work_link` (родитель → произведение → порядок). Книга находит свой цикл по цепочке `book.refBookId → произведения издания → родительский цикл` (fallback — по названию). Ничего не денормализуем в книгу.
3. **Отображение серии**: не пилюлей — обычной строкой в каталожной карточке («Изд. серия — …»).
4. **Отображение цикла**: на месте прежнего чипа серии — чип цикла («Харри Холе · №9»), по клику — **шторка цикла**: отсортированный список произведений. В строке две независимые оси: **чтение** (прочитана / читаю / ничего) и **наличие** (на полке / в «Хочу» / нет). Прочитанная книга может отсутствовать в библиотеке (читал давно, слушал в аудио) — кнопка «В „Хочу"» показывается по наличию и **никогда не блокируется статусом чтения**. Тап по строке с моей книгой — переход в её карточку, по отсутствующей — шторка произведения с изданиями.
5. **Карточка книги**: секция «Цикл» — соседние произведения цикла (компактно, «все N →» открывает шторку).
6. Источник циклов — только FantLab (OpenLibrary/Google циклов не имеют — проверено); у изданий OpenLibrary подхватываем строку series как издательскую серию, когда есть.
7. **Текстовый поиск каталога** больше не ищет по издательской серии — только название и авторы (плейсхолдер «Название или автор…»); фильтр по серии в шторке фильтров остаётся.

**Вне скоупа сейчас**: ручное создание и разметка циклов — позже, вместе с расширенными виш-листами и подборками.

## Вишлисты и подборки (M17)

Одна сущность, два вида: **вишлист** отвечает на вопрос «что хочу почитать», **подборка** — «что можно почитать по теме». Механика, экраны и шэринг общие, различаются только вид и слова в интерфейсе.

1. **Модель.** `book_list` (владелец, вид `wishlist`|`collection`, заголовок, описание, порядок) и `book_list_item` — ссылка ровно на одно из трёх: моя книга, произведение эталона, издание эталона; плюс необязательная заметка «зачем эта книга здесь». Элемент умеет ссылаться на эталон, потому что подборка «Китайская классика» состоит в основном из книг, которых нет в библиотеке, а каталог — это только мои книги. Если по эталону находится моя книга (логика из M16), строка помечается «на полке» и ведёт в карточку; иначе — на страницу произведения или издания.
2. **Порядок** — по добавлению, новое сверху. Перетаскивание отложено.
3. **Экраны.** Вход — страница «Чтение»: секции «Вишлисты» и «Подборки» с карточками (стопка мини-обложек, счётчик, описание в строку). `/lists/$listId` — просмотр, `/lists/$listId/edit` — заголовок, описание, вид, удаление.
4. **Добавление**: кнопка «+» вместо «В Хочу» (так никто не говорит) — одна шторка со всеми моими списками: вишлисты, подборки, и внизу поля «Новый вишлист…» / «Новая подборка…» для создания на лету, без ухода с экрана. Книга, которая уже в списке, помечена галочкой; повторный тап убирает. Кнопка живёт везде, где раньше было «В Хочу»: библиография автора, шторка цикла, страницы произведения и издания, карточка книги, каталог.
5. **Шэринг** — как у полок: область ссылки `list`, гостевая витрина и добавление к «Друзьям». Скрытые книги на витрине не показываются.
6. **Бронь подарка.** На витрине вишлиста гость жмёт «Дарю эту» (имя + бронь), книга помечается для других гостей как «уже дарят» — чтобы не подарили одно и то же. **Владельцу бронь не видна**: сюрприз сохраняется. Посмотреть можно осознанно — в меню списка пункт «Кто что дарит» с предупреждением про спойлер. Гость снимает свою бронь по той же ссылке.
7. **Миграция**: книги со статусом `wishlist` собираются в список «Хочу почитать», `/wishlist` ведёт на него. Фильтр каталога «Где книга: Хочу» продолжает работать.

8. **Сквозная индикация членства (доработка).** Книга существует в трёх формах — моя книга, произведение эталона, издание эталона, — и попасть в список могла в любой из них (мигрированный «Хочу» — это книги; «+» из библиографии кладёт произведение; «+» у издания — издание). Для читателя это одна книга, поэтому индикация резолвится сквозь связи: `book.refBookId/refWorkId`, `ref_book_work`, совпадение названий — тот же механизм, что «есть» в библиографии. Где показываем:
   - **страница произведения**: чипы списков под шапкой; кнопка «＋ В список» → «✓ В списках»; в строках изданий отметка у того издания, которое лежит в списке само по себе;
   - **страница издания**: чипы + отмеченная кнопка (учитывая и произведения этого издания);
   - **карточка книги**: чипы (включая случаи, когда в списке лежит произведение или издание этой книги);
   - **библиография автора и шторка цикла**: «+» в строке становится «✓»;
   - **шторка «+»**: галочка горит у списка, если книга там в любой форме; повторный тап убирает именно тот элемент, который там лежит;
   - **каталог**: индикации нет сознательно — карточки компактные, членство видно на карточке книги.
9. **Формы в списке — без путаницы.** В строке списка помечается форма элемента: штамп «произведение» / «издание» (у моих книг вместо этого место — «на полке …»). При добавлении **издания**, когда в списке уже лежит произведение той же книги, шторка предлагает заменить: «Заменить произведение этим изданием?» — [Заменить] / [Оставить оба]. При добавлении **произведения**, когда в списке уже есть его издание, предлагает пропустить: «Уже есть издание — можно не добавлять» — [Не добавлять] / [Всё равно добавить]. Оба предложения — мягкие подсказки, не запреты: сохранять можно как угодно.

10. **Форма книги: «Куда положить».** Свитч «Хочу» обещал виш-лист, но книга попадала в список только при следующем старте приложения (через миграционный бэкфилл) — заменяем на явный выбор: сегмент «На полку» / «В список». «На полку» — как раньше (библиотека, полка, статус «дома»). «В список» — книга сохраняется со статусом `wishlist` без полки и **сразу** кладётся в выбранный список; в выборе все мои списки двумя группами, по умолчанию первый вишлист, рядом — создание нового. Если списков нет, показывается только поле создания. Книгу, которая есть дома, в подборку кладут после сохранения кнопкой «+» на карточке.

**Вне скоупа**: соавторы списков, умные (автоматические) подборки, ручная разметка циклов.

## Сканирование пачкой: нераспознанные книги (M18)

Реальный разбор завала — это стопка на столе и телефон в руке: сканировать надо подряд, а не залипать на каждой книге, которую не нашли источники. Ввод названия руками с телефона медленный, поиск в интернете — тем более.

1. **Две кнопки сохранения** в форме: «Сохранить и добавить ещё» (возврат к сканеру) и «Сохранить» (открывает карточку). «Пропустить» и «Отмена» — во вторичном меню панели: пропуск просто закрывает черновик и возвращает к сканеру, ничего не сохраняя и ни о чём не спрашивая.
2. **Сохранять можно по одному ISBN**: названием временно служит сам номер, книга помечается флагом `unrecognized` и попадает в «Не распознано». Без номера название обязательно. Как только название заполнено руками или найдено, флаг снимается сам.
3. **Экран «Не распознано»** — все болванки в одном месте: ISBN моноширинным, дата добавления, действия «Заполнить» (форма правки) и «Найти снова» (повторный поиск в источниках), плюс общая кнопка «Проверить все». Вход — маленькая кнопка-счётчик «Не распознано · N» в сканере и в «Неразобранном».
4. **Автоматического дораспознавания нет** — только по кнопке: фоновые попытки молча меняли бы карточки.
5. **В списках** болванка показывается номером и штампом «не распознана», чтобы её нельзя было спутать с обычной книгой; поиск по каталогу находит её по ISBN.

## Настройки (M19)

Профиль и пароль — там, где их ищут.

1. **Страница «Настройки»** (вход — меню под именем в шапке, рядом с «Выйти»):
   - **Профиль**: имя и почта с правкой. Почта — это логин; писем приложение не шлёт.
   - **Пароль**: смена по текущему паролю. Восстановления по почте нет и не может быть (SMTP отсутствует) — так и написано под полем; забытый пароль сбрасывает владелец сервера.
   - **Аккаунт**: выход.

## Книги без ISBN: поиск по названию (M20)

У советских и ранних постсоветских изданий ISBN нет вообще (на выходных данных вместо него «ЛР» и «ИБ» — лицензия издательства и номер издательской бумаги). Сканер таким книгам не поможет никогда, а набирать карточку целиком с телефона мучительно.

1. **Вкладка «По названию»** в потоке добавления. Порядок вкладок: «Сканер», «ISBN», «По названию», **«Вручную» — последней**: ручной ввод остаётся честным запасным вариантом, но предлагается в конце.
2. **Три источника, по возрастанию цены запроса**: свои книги (предупреждение о дубле), эталонный каталог Полки (мгновенно, без сети), затем FantLab `search-works` — он хорошо знает русскую классику (по «Братья Карамазовы» — 25 совпадений, первым Достоевский). OpenLibrary — запасной; Google Books по кириллице слаб и упирается в дневной лимит.
3. **Выбор произведения → черновик** с названием, автором и годом. Если у произведения есть издания в эталоне — показываем их: выбранное издание заполняет издательство, год, страницы и обложку. Издания нет — остаётся дописать выходные данные с последней страницы (издательство, год, том); это несколько полей вместо всей карточки, а книга уже связана с эталоном и попадает в библиографию автора и в циклы.
4. **«Добавить на полку»** на страницах произведения и издания: сейчас оттуда можно только в список, а книга в руках — это книга дома.

## Роли и пост-модерация (M21)

Пока пользователей трое, «запрещёнка» — абстракция; на сотне аккаунтов это ответственность владельца сервера. Готовим заранее.

**Что модерируем — общий слой, не личное:**

- **загруженные обложки** — файлы лежат на нашем диске и раздаются по ссылкам;
- **эталонный каталог** (произведения и издания) — он общий для всех, попадает в поиск и на страницы авторов, ничьей личной собственностью не является;
- **публичные витрины и расшаренные списки** — их названия, описания и состав.

**Что не модерируем:** приватные рецензии, личные заметки, домашние библиотеки без ссылок. Читать личное ради подстраховки — плохой размен.

1. **Роли**: `user` / `moderator` / `admin`. Внутрибиблиотечные роли (владелец, участник) остаются как есть — это про доступ к своим книгам, а не про сервис. Администратор назначает модераторов и управляет аккаунтами; модератор разбирает очередь.
2. **Пост-модерация**: публикация не задерживается — ссылка работает сразу, а объект попадает в очередь со статусом «на проверке». Модератор помечает «в порядке» или снимает с публикации, обязательно указывая причину.
3. **Жалобы**: кнопка «Пожаловаться» на публичной витрине, доступная и гостю без аккаунта. Жалоба поднимает объект в начало очереди и показывает счётчик.
4. **Санкции** (все — с причиной, всё пишется в журнал): снять с публикации, удалить файл обложки, запретить пользователю публиковать (аккаунт живёт, новые ссылки создавать нельзя), заблокировать аккаунт.
5. **Обратная связь владельцу**: письмо отправить не можем, поэтому на его странице появляется плашка «Снято модератором · причина» — и объект остаётся в его личном каталоге.
6. **Журнал модерации**: кто, что, когда и почему. Без него разбор спорных случаев невозможен, а модерация превращается в произвол.
7. **Возрастная маркировка** пока не вводится — вернёмся, когда появятся реальные случаи.
8. **Правила сервиса** — публичная страница `/rules`, открывается без входа: что считается личным, что становится публичным, чего публиковать нельзя, как работает модерация и что делать при несогласии с решением. На неё ссылаются шторка жалобы, плашка о снятии, настройки и подвалы витрин. Контакт владельца в конце страницы — плейсхолдер, вписать перед выходом за круг друзей.

## Почта: SMTP и письма (M22)

Пока писем нет, «забыл пароль» решается только через владельца сервера, а смена почты с опечаткой навсегда отрезает вход. Подключаем SMTP — настраивается целиком в приложении.

1. **Раздел «Сервис»** — один вход из меню под именем, внутри вкладки: «Очередь», «Пользователи», «Почта», «Журнал». Разъехавшиеся админские страницы (`/moderation`, `/moderation/users`, `/moderation/log`) собираются сюда же.
2. **Настройки SMTP**: хост, порт, шифрование (нет / STARTTLS / TLS), логин, пароль, отправитель — имя и адрес. Кнопка «Отправить тестовое письмо» пишет результат прямо под формой: успех, отказ сервера или таймаут.
3. **Пароль SMTP хранится в базе зашифрованным** (AES-GCM, ключ выводится из `BETTER_AUTH_SECRET`) и обратно не показывается — только «сохранён», с возможностью заменить. В журнал пишется факт изменения настроек, без значений.
4. **Письма** — четыре вида, каждый включается отдельно:
   - **сброс пароля**: на входе появляется «Забыли пароль?», письмо со ссылкой на час; пока SMTP не настроен, ссылки нет и показывается прежнее объяснение;
   - **приглашение**: вместо копирования ссылки можно ввести адрес — человек получит письмо;
   - **подтверждение смены почты**: новый адрес подтверждается письмом, до подтверждения вход остаётся по старому;
   - **уведомления**: владельцу — о заявке «хочу почитать» и о снятии его публикации модератором.
5. **Если SMTP не настроен или сломался**, приложение работает как раньше: ссылки копируются руками, сброс пароля недоступен. Ошибки отправки идут в журнал приложения с текстом ответа сервера — молчать нельзя.

## Тёмная тема (M23)

Не инверсия светлой: «живые полки» — фирменный приём Полки, и в темноте дерево должно остаться деревом.

1. **Характер — «тёплая ночь»**: фон угольный с коричневым подтоном (`#17150F`), карточки `#1F1B14`, текст тёплый белый. Доска полки и патина светятся деревом, штампы синеют светлее, зелёный «ламповый» акцент осветляется до `#6FAE86` — иначе на тёмном он проваливается.
2. **Переключение**: по умолчанию как в системе (ночью телефон переключит сам), плюс ручной выбор «Светлая / Авто / Тёмная». Выбор хранится **в браузере**, а не в профиле: телефон и ноутбук живут разной жизнью.
3. **Где переключать**: быстрый сегмент в меню под именем, рядом с «Настройками»; там же дублируется в настройках.
4. **Реализация — только токены**: компоненты о теме не знают, меняются значения переменных. Тени в темноте не читаются — вместо них тонкая тёплая кромка и мягкое свечение.
5. **Корешки книг** окрашены из обложек и на тёмном фоне выглядят кислотно — поверх ложится общая вуаль цвета фона: книги садятся в темноту, но остаются различимыми. Сами обложки не трогаем, это фотографии.
6. **Без мигания**: тема применяется до первой отрисовки маленьким скриптом в начале страницы, иначе при загрузке вспыхивает белым.

## ИИ-помощник: подключение (M24)

Зарубежные модели до российских книжных источников не дотягиваются, поэтому провайдер — Yandex AI Studio. Ключ и каталог владельца, доступ у всех пользователей с суточным лимитом на каждого.

**Этот этап — только подключение.** Никаких функций: делаем нейронку доступной и проверяемой, дальше внедряем сценарии по одному, каждый отдельным этапом со своим макетом.

1. **Настройки** — «Сервис» → «ИИ», по образцу рабочего экрана владельца из соседнего проекта:
   - главный тумблер «Использовать ИИ»;
   - **провайдер** списком (Yandex AI Studio; задел на OpenAI-совместимые);
   - **API-ключ** — в базе зашифрованным; в поле показывается «(задан)», пустое поле означает «не менять»;
   - **идентификатор каталога** (folder ID);
   - **модель** — выпадающий список с поиском, **подгружаемый по ключу и каталогу**, а не захардкоженный: провайдеры меняют состав моделей чаще, чем мы выкатываемся. Если список получить не удалось — поле остаётся вводимым руками;
   - **статус**: «ИИ отвечает · последний раз <дата>» либо дословная ошибка API;
   - **суточный лимит** запросов на пользователя.
2. **Внутри — тонкий слой** `services/ai.ts`: одна функция «спросить модель» с таймаутом, счётчиком лимита, записью в журнал (запрос, модель, токены, длительность, ошибка). Всё, что появится дальше, ходит только через неё.
3. **Принцип для всех будущих функций** (утверждается сейчас, чтобы не переделывать): модель **ничего не меняет сама** — только предлагает. Изменение вносится по кнопке «Применить», помечается «предложил ИИ» и **откатывается** к прежнему значению в один тап; для этого предложение хранит и новое значение, и прежнее.

**Дальше, по одному этапу на сценарий** (порядок обсудим): аннотация, когда её нет · тэги и жанры · разбор нераспознанных · парсинг и дозаполнение карточек · раскладывание по полкам · описания подборок и советы · подсказки модератору.

## ИИ: разбор нераспознанных (M25)

Первая функция ИИ. Работает там, где после сканирования осталась болванка:
ISBN есть, названия нет, источники молчат.

**Почему не «модель заполняет карточку».** Языковая модель не знает номеров —
она знает книги. ISBN выглядит осмысленным, и на него легко сочинить
правдоподобную книгу. Поэтому ответ модели служит только подсказкой для
поиска: название и автора мы прогоняем через свой каталог, и данные берём из
найденного издания. Отсюда четыре исхода:

- **Подтверждено** — издание с этим номером нашлось в эталоне (часто после
  того, как по названию подтянулись издания произведения с FantLab). Карточка
  заполняется из каталога.
- **Книга есть, издание — не то** — произведение нашлось, а издания с номером
  нет. Предлагаем выбрать издание руками.
- **Не подтверждено** — каталог молчит; применить можно, но с пометкой.
- **Модель не знает** — честный отказ, уходим в ручную форму.

**Что известно без модели.** Издательство читается из префикса номера
(`978-5-17` — АСТ, `978-5-04` — Эксмо, `978-5-389` — Азбука-Аттикус). Это
арифметика, а не гипотеза, и для книг 90-х часто единственное достоверное.

**Модерация и своя база.** Применённое ИИ висит с пометкой «Заполнил ИИ · не
проверено» и попадает в «Сервис → ИИ → На проверке». Модератор сверяет с книгой
и решает: «В эталон» (запись становится общей, `source='manual'`), «Поправить»
или «Отклонить» (с причиной; карточка возвращается к ISBN, а негодный ответ
модели помечается как непригодный). Только после проверки человеком запись
попадает в общий эталон — иначе одна выдумка расползётся по всем библиотекам.

**Экономия.** Ответ по каждому номеру сохраняется, включая «не знаю»: второй
раз тот же ISBN модели не уходит ни у кого. Порядок обращения всегда: свой
эталон → внешние источники → и только потом модель. Утверждённое в эталоне
находится дальше мгновенно и бесплатно.

**Пределы.** Насколько модель угадывает русские ISBN — вопрос практики. Если
подтверждений окажется мало, следующий шаг — распознавание фото обложки и
выходных данных, это отдельный этап.

## ИИ: поиск в интернете по ISBN (M26)

Языковая модель номеров не знает и знать не может: ISBN — случайное число, а не
факт о книге. Проверено на 29 нераспознанных: модель не угадала ни одного.
Зато номер лежит в интернете — на страницах магазинов и библиотек, вместе с
полными выходными данными. Значит модели нужен не «опыт», а **поиск**.

Инструмент — **Yandex Search API** (та же AI Studio, тот же ключ и каталог;
нужна активация услуги и роль `search-api.webSearch.user`).

**Два режима, переключатель в настройках.**

1. **Поиск + извлечение** (по умолчанию, дёшево). `POST /v2/web/search`: по
   номеру получаем выдачу, берём заголовки и сниппеты первых результатов,
   модель извлекает из них название, автора, издательство, год, объём.
   ≈50–200 ₽ за 1000 поисков плюс копейки за разбор.
2. **Генеративный ответ** (дороже, ≈5 ₽ за книгу). `POST /v2/gen/search`:
   модель сама ищет и отвечает, возвращая список использованных источников.
   Включается, когда первый режим не справился, или насовсем — как решит
   владелец.

**Доказательство вместо доверия.** Данные принимаются, только если сам ISBN
встретился в тексте найденной страницы. Тогда это цитата, а не фантазия, и в
карточку кладётся ссылка на страницу. Если номер в выдаче не встретился —
вердикт «не подтверждено», как и раньше.

**Порядок обращения** (каждый следующий шаг только если предыдущий молчит):
свой эталон → FantLab · Google Books · OpenLibrary → веб-поиск с извлечением →
генеративный ответ (если включён) → ручная форма. Веб-поиск считается по
своему суточному лимиту, отдельно от лимита модели: он стоит денег.

**Что будет видно человеку.** В разборе — цепочка попыток и кто ответил;
у найденного — ссылка «нашли на labirint.ru, ISBN совпал». В очереди
модератора — тот же источник со ссылкой, чтобы сверять было по чему.

## Одна кнопка «Найти» (M26.2)

Способ поиска — забота приложения, не человека. На «Не распознано» одна кнопка
**Найти**: она молча проходит цепочку эталон → FantLab · Google Books ·
OpenLibrary → поиск в интернете → модель и останавливается на первом, кто
ответил. Платный генеративный поиск включается тумблером в настройках («если не
нашлось»), а не кнопкой на каждой книге.

Дальше решает человек: **Сохранить** (данные в карточку, пометка «Заполнил ИИ ·
не проверено» для модератора), **Не то** (книга остаётся в списке, ответ
помечается негодным и второй раз не предлагается), **Заполнить руками**.
Отчёт по источникам спрятан под «Подробнее».

**«Искать дальше» (M26.3).** Если первый ответивший путь вернул не то
(латиница из OpenLibrary, чужое издание) — кнопка отвергает вариант и
продолжает цепочку со следующей ступени. Отвергнутое запоминается и повторно
не показывается; когда пути кончились — «вариантов больше нет», остаётся
ручная форма.

**Полный результат сразу.** Добор обложки, аннотации и объёма встроен в конец
цепочки: чем бы книга ни нашлась (каталог, поиск, модель), перед показом
добираются недостающие поля — Google по названию, og-теги страницы-
доказательства, Яндекс Картинки. «Сохранить» кладёт в карточку всё разом.
Ссылку на обложку у языковой модели не спрашиваем никогда: URL она выдумывает;
обложку даёт страница, которую нашёл поиск.

**Ядро переиспользуемо.** Вся цепочка — `recognizeIsbn(userId, isbn13)`, без
привязки к книге: следующий этап (поиск сразу после скана, M28) зовёт её же.

**Найти данные на карточке книги.** Как только название появилось, книга уходит
из «Не распознано» — а обложки и аннотации может не быть. Поэтому в меню «Ещё»
есть «Найти данные»: показывает, что именно заполнится, и трогает **только
пустые поля** — введённое руками не перетирается.

## ИИ: фото выходных данных (M27, план)

Остаются книги, которых нет ни в источниках, ни в выдаче — старые издания и
малотиражки. Для них единственный достоверный носитель — сама книга.

Сценарий: на странице «Не распознано» кнопка «Сфотографировать» → камера →
снимок страницы с выходными данными (оборот титула) → **Yandex Vision OCR**
достаёт текст → модель раскладывает его по полям карточки → человек
подтверждает. Обложку снимаем тем же заходом, вторым кадром.

Здесь у нас впервые появляется настоящее доказательство: распознанный текст
самой книги. Поэтому такие записи после проверки модератором ложатся в эталон
с пометкой «с книги в руках» — надёжнее любого источника.

## Ключевые сценарии

1. **Разбор завала.** Алексей с телефоном у стопки книг: открыл «Добавить» → выбрал библиотеку → сканирует подряд: пик — черновик — поправил полку — сохранил — «Добавить ещё». Непонятные книги падают в «Неразобранное», раскладываются по полкам позже с ноутбука.
2. **Дал почитать.** Друг уносит книгу: на карточке «Дать почитать» → имя, срок. Книга получает штамп «НА РУКАХ». Через месяц в `/loans` видно, у кого что; вернули — отметил возврат, запись ушла в историю.
3. **Гость просит книгу.** Друг открывает присланную ссылку, листает полку, жмёт «Хочу взять почитать» на детективе, пишет имя. Владелец в `/requests` одобряет — создана выдача. При встрече передаёт книгу.
4. **Серия.** Куплен третий том цикла: при добавлении по ISBN серия подтянулась сама; на странице серии видно тома 1–3 по порядку и чего не хватает (визуально, по номерам).
5. **Подарил.** Книга уехала к маме насовсем: статус «Подарена» (кому+когда) — с полки исчезла, в каталоге находится фильтром «подаренные».
6. **Семейная библиотека.** Алексей приглашает Олю инвайт-ссылкой — «Дом» теперь общий: Оля добавляет свои книги на те же полки, ставит свои оценки; выдачи и заявки видят оба; у каждого свой виш-лист и свои рецензии.

## Критерий готовности MVP

Сквозной сценарий на проде с телефона: регистрация → библиотека + полки → отсканировать стопку → разложить «Неразобранное» → оценка + рецензия → «дал почитать» → share-ссылка другу → заявка «хочу почитать» → одобрение → возврат. Плюс: патина/акценты полок работают, поиск по-русски работает, рестарт контейнера ничего не теряет.
