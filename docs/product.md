# Polka (Полка) — продуктовая спецификация MVP

## Что это и зачем

Polka — веб-приложение для ведения домашней библиотеки **бумажных** книг (в основном на русском языке). Главная боль владельца: книжные завалы, которые нужно разобрать, и отсутствие удобного инструмента для этого. Существующие сервисы либо про электронное чтение, либо неудобны для учёта физических книг.

Масштаб: личное пользование — владелец + пара друзей. Это осознанное ограничение MVP, а не временное упущение.

Форм-фактор: современное веб-приложение, mobile-first (основной сценарий разбора завалов — с телефоном в руках у полки), устанавливается на домашний экран (PWA-manifest). Задел на кроссплатформу (позже возможен Capacitor).

## Роли

| Роль                 | Кто это                                                 | Что может                                                                                                                      |
| -------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Участник библиотеки  | Зарегистрированный пользователь, состоящий в библиотеке | Всё внутри неё: книги, полки, выдачи, ссылки, заявки. У библиотеки может быть **несколько совладельцев** (семейная библиотека) |
| Создатель библиотеки | Участник-основатель                                     | То же + приглашает/удаляет участников, может удалить библиотеку                                                                |
| Гость                | Человек со секретной ссылкой, без аккаунта              | Смотреть расшаренную библиотеку/полку; отправить заявку «хочу взять почитать» (имя + записка)                                  |

Аккаунты друзей с их оценками/комментами — фаза 2.

**Регистрация — по приглашению.** Пустая система: первый пользователь регистрируется свободно. Дальше единственный способ создать аккаунт — одноразовая ссылка-приглашение `/join/<токен>` (живёт 7 дней), которую генерирует любой зарегистрированный («Друзья» → «Пригласить в Полку»). Никаких флагов окружения.

## Структура каталога

- **Библиотека** — физическое место (дом, дача, кабинет). У пользователя их может быть несколько. **Совладение**: в библиотеке может состоять несколько пользователей (муж и жена ведут один «Дом», книги не делятся по аккаунтам). Приглашение — инвайт-ссылкой: залогиненный человек открывает её и становится участником. Все участники полноправны в каталоге; создатель дополнительно управляет составом участников.
- **Полка** — внутри библиотеки, упорядочены вручную. У полки может быть **акцентный цвет** (см. «Живые полки» в ux-ui-guideline).
- **Книга** стоит ровно на одной полке **или** лежит в «Неразобранном» своей библиотеки (инбокс для разбора завалов).
- **Серия** — самостоятельная сущность для группировки книг: издательская серия («Чёрная кошка») или авторский цикл (детективы про одного сыщика). Серия глобальна для пользователя — её книги могут стоять на разных полках и в разных библиотеках. У книги не более одной серии + номер тома (свободный текст: «3», «3.5», «3–4»); вторичные группировки — тэгами.
- **Тэги** — свободные метки пользователя (жанры, «подарить маме», что угодно). Книга ↔ тэги: многие-ко-многим.

## Карточка книги

Поля: название*, авторы (текстом: «Фамилия Имя; Фамилия Имя»), ISBN-10, ISBN-13, издательство, год издания, серия + № тома, число страниц, язык (по умолчанию `ru`), аннотация, обложка (файл: загрузка или скачивание из найденных метаданных), приватные заметки владельца, тэги.

### Статус владения (ровно один)

| Статус       | Смысл                   | Поведение                                                                                                                   |
| ------------ | ----------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `in_library` | Стоит дома              | Видна на полке/в «Неразобранном»                                                                                            |
| `wishlist`   | «Хочу» — ещё не куплена | Личный список `/wishlist` каждого пользователя, без библиотеки/полки; после покупки назначается полка и статус `in_library` |
| `gifted`     | Подарена (кому + когда) | Уходит с видов полок; находится фильтром в каталоге                                                                         |
| `lost`       | Потеряна                | Аналогично `gifted`                                                                                                         |

Принцип: **полка отражает физическую реальность** — чего нет в доме, того нет на полке.

### «На руках» (выдачи)

«Дал почитать» — не статус владения, а **журнал выдач**: кому (имя текстом), когда, срок (опционально), записка, дата возврата. Активная выдача (без даты возврата) — максимум одна на книгу; книга при этом остаётся на полке визуально, но помечена штампом «НА РУКАХ». Страница `/loans`: активные выдачи + история. История выдач видна и на карточке книги.

### Чтение и оценка — личные у каждого участника

- Статус чтения: `unread` / `reading` / `read` / `abandoned` + дата прочтения.
- Оценка 1–5 (звёзды) и рецензия (свободный текст).
- Приватные заметки.

В общей библиотеке эти поля у каждого участника **свои**: муж и жена читают и оценивают одну книгу независимо. Карточка показывает оценки всех участников («Алексей ★5 · Оля ★4») и рецензии рядом; заметки видны только автору. Общие у книги: библиографические поля, полка, тэги, выдачи, статус владения.

## Добавление книг

Три равноправных пути, оптимизированных под «стопку книг на полу»:

1. **Сканер штрихкода** камерой телефона (EAN-13 → ISBN) — основной для массового ввода.
2. **Ввод ISBN** вручную (13 или 10 цифр, с дефисами или без).
3. **Полностью вручную** — форма с нуля.

После скана/ввода ISBN приложение ищет метаданные в интернете (Google Books + OpenLibrary + FantLab, см. architecture.md) и показывает **черновик карточки**, который пользователь правит и подтверждает. Найденное название серии предзаполняет выбор серии (создастся при сохранении, если новой).

**Честное ожидание:** для современных русских ISBN автозаполнение срабатывает примерно в 40–70% случаев, для книг 90-х — хуже. Поэтому ручная форма — первоклассный сценарий, а «ничего не нашлось» мгновенно превращается в ручную форму с уже заполненным ISBN. UX обязан оставаться приятным при 0% попаданий.

Поток «разбор завала»: сохранил книгу → кнопка «Добавить ещё» возвращает сразу к сканеру; выбранные библиотека/полка (или «Неразобранное») — липкие между добавлениями. При совпадении ISBN-13 с существующей книгой — предупреждение о дубле (дубль сохранить можно: бывают два экземпляра).

## Каталог и поиск

Раздел «Каталог» — глобальный поиск с фильтрами. Строка поиска: название, авторы, название серии — регистронезависимо **для кириллицы**. Полнотекстовый поиск (FTS5) — после MVP.

**Фильтры (M10, макет `docs/design/catalog-v2.html`).** На мобильном — кнопка «Фильтры» со счётчиком активных, открывает шторку; применённые фильтры видны чипами с крестиками прямо на странице. Именование: «**Где книга**» — местонахождение (дома / на руках / хочу / подарены / потеряны / скрытые), «**Статус чтения**» — не читал / читаю / прочитал / бросил. Секции шторки: где книга, библиотека и полка, статус чтения, **автор** (ввод + частые авторы чипами), **период издания** (от–до + пресеты), серия, тэги. Отдельной сущности «жанр» нет — жанры ведём тэгами; настоящие жанры из метаданных — кандидат в v2. Кнопка шторки показывает живой счётчик: «Показать N книг». На десктопе фильтры остаются строкой селектов.

Два скоупа поиска:

- **Мои книги** — весь свой каталог.
- **У друзей** — поиск по сохранённым чужим полкам (см. «Полки друзей» ниже). В результатах видно, у кого книга и свободна ли она; отсюда же заявка «Хочу почитать» в один клик (имя подставляется из профиля).

## Шэринг и заявки

- Владелец создаёт **секретную ссылку** на библиотеку или полку (`/s/<токен>`). Ссылку можно отозвать.
- Гость по ссылке видит read-only витрину: книги с обложками, авторами, годом, серией, аннотацией и статусом «на руках/свободна». **Не видны**: приватные заметки, имена должников, статусы чтения, оценки и рецензии — наружу отдаётся явный белый список полей.
- На карточке книги гость может отправить заявку **«Хочу взять почитать»**: имя + записка (без регистрации).
- Владелец видит заявки в инбоксе `/requests` (бейдж в навигации) и либо отклоняет, либо **одобряет — заявка превращается в выдачу** с предзаполненным именем.

### Раздел «Друзья»

Отдельный раздел в навигации, две вкладки:

**Полки друзей** (входящие). Залогиненный пользователь, открыв чужую share-ссылку, может **сохранить её себе**. Сохранённые полки/библиотеки видны карточками (чья, название, сколько книг), открываются в витрину; можно убрать. Отозванная владельцем ссылка пропадает сама. После сохранения:

- в Каталоге появляется скоуп «У друзей» — поиск по всем сохранённым полкам сразу (публичные поля, как на витрине);
- заявка «Хочу почитать» отправляется в один клик от имени профиля.

**Мои ссылки** (исходящие). Управление своим шэрингом: создать ссылку на библиотеку/полку, скопировать, отозвать; видно, сколько заявок пришло по каждой.

Аккаунтов-«друзей» и подписок в MVP по-прежнему нет — всё держится на ссылках.

## Раздел «Чтение» (личный хаб)

**Зачем.** Мобильная навигация упирается в пять слотов таббара: «Хочу», «Серии» и «Заявки» с телефона недостижимы, а вкладка «На руках» занимает целый слот ради редких заходов. «Чтение» — личная приборная панель читателя: не «найти книгу» (это Каталог), а «что у меня сейчас происходит». Каталог отвечает на запрос, «Моё» показывает состояния; его секции — быстрые входы в полные списки, данные не дублируются.

**Навигация после изменения.**

- Мобильный таббар: Библиотека · Каталог · [+] · **Чтение** (иконка-закладка) · Друзья.
- Десктоп-меню: Библиотека · Каталог · Серии · **Чтение** · Друзья · Заявки («Хочу» и «На руках» уходят внутрь «Чтения»).
- `/loans` и `/wishlist` остаются полными страницами — в них ведут секции «Чтения».
- Плавающая кнопка «+» остаётся приподнятой (это фича), но контент страниц получает нижний отступ, чтобы она ничего не перекрывала.
- В фильтр статуса Каталога добавляется пункт **«На руках»** — выданные книги находятся и поиском.
- Кнопка «+» — единственная постоянная точка добавления. Контекстные кнопки «Добавить» на страницах библиотеки/полки/каталога убираются как дубли; остаются только в пустых состояниях, где приглашают к первому действию.

**Секции страницы `/reading`** (сверху вниз; пустые секции скрываются целиком):

1. **Читаю сейчас** — книги с моим статусом чтения «читаю»: крупные обложки на полочной линии, под ними название, автор и «с {дата}». Тап — карточка книги.
2. **На руках · N** — активные выдачи: мини-обложка, название, «у «Имя»» с датой (просрочка подсвечивается), кнопка «Вернули» прямо в строке. Ссылка «Вся история →» на `/loans`.
3. **Хочу · N** — первые книги виш-листа (название, автор), ссылка «Весь список →» на `/wishlist`. Сценарий: быстро свериться в магазине.
4. **Прочитано в {год}** — счётчик книг за календарный год и средняя оценка; ссылка в Каталог с фильтром «прочитанные».

**Данные.** Одна серверная функция `getReadingHubFn` собирает всё за один запрос страницы: читаемые книги (личный слой текущего пользователя), активные выдачи по моим библиотекам, головка виш-листа + счётчик, счётчик прочитанного за год. Всё в рамках членства в библиотеках (`assertMember`), как везде.

**Пустое состояние всей страницы** (новый пользователь): подсказки-приглашения «Отметьте на карточке книги „Читаю“», «Добавьте первую книгу в „Хочу“».

**Открытый вопрос (решает владелец).** «В планах» как отдельный статус чтения (книга дома, хочу прочитать — не то же самое, что виш-лист «хочу купить») в MVP не вводим; если окажется нужным — добавим статус в личный слой позже.

## Разбор книг на мобильном

Массовое перемещение (раскладка «Неразобранного» по полкам) с телефона сейчас неудобно: мелкие чекбоксы, модальный диалог с дефолтом «первая библиотека по списку», после перемещения пользователь остаётся в отфильтрованном каталоге.

**Решения.**

1. **Отдельная страница «Разбор» (`/unsorted`).** «Разобрать стопку» из библиотеки ведёт на чистый список неразобранных книг — без фильтров и поиска, весь список сразу в режиме выбора: тап по карточке отмечает книгу с первого касания. В каталоге и на полке массовый выбор тоже есть (первый тап — по крупному чекбоксу, дальше тап по карточке; поиск и фильтры на время выбора прячутся).
2. **Панель выбора занимает место таббара** (как в нативных приложениях, ничего не перекрывает): «N кн.» · кнопка «Переместить» · круглая «✕».
3. **Шторки вместо диалогов.** На мобильном все модальные окна приложения открываются нижними шторками (ручка, скругление сверху, safe-area); на десктопе остаются центрированные диалоги. Реализация — адаптив в базовом Dialog, без переписывания вызовов.
4. **Умная шторка перемещения**: библиотека предвыбрана по выбранным книгам (общая библиотека выделения, а не первая по списку); полки — вертикальный список радио-строк (тап выбирает), «Неразобранное» первой строкой. Внизу списка — «+ Новая полка»: имя вводится тут же, полка создаётся и сразу выбирается — без возврата в другие меню.
5. **После перемещения**: если в текущем списке остались книги — остаёмся разбирать дальше; если список опустел — переходим на целевую полку.

## Скрытые книги

Иногда книгу не хочется показывать гостям: она стоит на полке, но на витринах ей делать нечего.

**Правила видимости.**

- «Скрыть» — свойство книги (`hidden`), переключают участники библиотеки; **все совладельцы видят скрытые книги** как обычно (это приватность от гостей, не от семьи).
- Скрытая книга **не попадает**: на публичные витрины `/s/<токен>` (и в их счётчики), в поиск «У друзей» у тех, кто сохранил ссылку, в гостевые заявки (сервер отклоняет заявку на скрытую книгу), в публичную раздачу обложек (`/api/covers` для гостей).
- На своих полках и в каталоге книга стоит как обычно — она физически дома.

**Индикация и управление.**

- В списках (каталог, полка, «Чтение») — значок перечёркнутого глаза в строке метаданных.
- На карточке книги — чип «Скрыта» под строкой издания; в меню «Ещё» — пункт «Скрыть» / «Не скрывать»; тост поясняет: «видна только владельцам библиотеки».
- В фильтре статуса каталога — пункт «Скрытые», чтобы найти все разом.

## Реалистичные корешки (полка как место поиска книги)

Задача — чтобы полку в приложении можно было визуально сопоставить с физической: нашёл глазами дома → нашёл в приложении. Цвет уже есть (акцент обложки); добавляем честные размеры и вид переплёта.

**Данные книги (новые поля).**

- `coverType` — переплёт: `soft` (мягкая обложка) / `hard` (твёрдый переплёт) / `gift` (подарочное издание); null = неизвестно.
- `heightMm` — высота книги в миллиметрах; null = неизвестно.
- Источники: **FantLab** отдаёт `format_mm` («145x215» → высота 215) и `cover_type» («твёрдая»/«мягкая») — заполняем при добавлении по ISBN; вручную — в форме книги (селект переплёта + высота в мм). **Сам ISBN физических размеров не кодирует** (префикс GS1 · группа · издатель · номер · контроль) — проверено, размер берём только из метаданных и рук.

**Геометрия корешка (единая для полки и стопки).**

- Толщина: непрерывно от страниц — `14 + страницы/14` px, зажато 18–56 (было 5 ступеней).
- Высота: `мм × 0.62` px, зажато 96–168. Фолбэк без мм — по переплёту (мягкая ≈118, твёрдая ≈138, подарочное ≈152), дальше — детерминированная вариация от названия, как сейчас.
- Вид: **мягкая** — плоский корешок со скруглением и лёгким бликом; **твёрдая** — кант (крышки чуть выступают сверху и снизу); **подарочное** — кант + золотое тиснение текста и ляссе (ленточка-закладка снизу).
- **Стопка «Неразобранное»** — те же книги лёжа: высота плашки = толщина корешка, длина = высота книги. Одна и та же книга выглядит одинаково на полке и в стопке.

**Сопутствующее.** Иконка вкладки «Библиотека» — стеллаж (`Library`) вместо домика; наклонённые корешки («на руках») больше не обрезаются сверху (запас в контейнере полки).

### Страница полки (M10)

Макет `docs/design/shelf-page-v2.html`. В шапке остаются: крошки, название, счётчик книг и одна кнопка «Ещё».

### Форма книги (M10)

Макет `docs/design/book-form-v2.html`. Решения: **поле «Высота, мм» убрано** (никто не измеряет книги линейкой — высота корешка заполняется только из FantLab, фолбэк — переплёт); **переплёт — чипы** с именованиями книжных магазинов («Не знаю / Мягкая обложка / Твёрдый переплёт»; интегральный из FantLab маппится в мягкую); **«Подарочное издание» — отдельный переключатель** (тип издания, не переплёт): на корешке отражается только габаритами по умолчанию (выше и толще), декор с золотом и ляссе убирается; в данных `coverType: soft|hard` + `giftEdition: boolean` (существующие `gift` мигрируют в `hard + giftEdition`); все поля ≥48px со шрифтом 16px (iOS не зумит), цифровые — mono с числовой клавиатурой; «Хочу» — строка-переключатель; кнопки сохранения — **липкая панель снизу** (primary «Сохранить и добавить ещё» + «···» с остальными вариантами), чтобы не скроллить длинную форму.

## Свой каталог-эталон и авторы (план M13–M15)

Цель — независимость от внешних сервисов: свой справочный слой данных, который наполняется из API один раз, а дальше живёт у нас. Пользовательские записи — всегда копии; эталон неизменяем; поиск метаданных — только по эталону.

### M13 — Сущность «Автор»

- Таблицы: `author` (id, name, nameNorm, fantlabId nullable, createdAt; дедуп по nameNorm) и `book_author` (bookId, authorId, position — порядок соавторов).
- Строка `book.authors` остаётся денормализованным отображением (карточки, корешки, формы не меняются); сервер синхронизирует связки при создании/правке книги.
- Миграция существующих книг: разрез строк по «;», дедуп, связки.
- FantLab при lookup отдаёт `[autor=14093]…[/autor]` — кладём `fantlabId` сразу.
- Страница автора `/authors/$id`: его книги на моих полках; имена авторов в карточке книги становятся ссылками.
- Фильтр и фасет «Автор» в каталоге переезжают с LIKE-эвристик на таблицу.
- Ролей (переводчик, составитель) сознательно нет.

### M14 — Эталонный каталог изданий

- Таблица `ref_book`: source + sourceId (unique), isbn13/10 (индекс), title, publisher, year, pages, heightMm, coverType, annotation, seriesName, coverUrl (внешний), rawJson, fetchedAt; связка `ref_book_author` (authorId из M13, position).
- **Неизменяемость**: пользователь эталон не редактирует; обновление — только повторным фетчем.
- Порядок lookup при добавлении книги: **сначала свой `ref_book` по ISBN**, при промахе — внешние API, их ответы сохраняются в `ref_book` (заменяя со временем `lookup_cache`).
- `book.refBookId` (nullable) — связь экземпляра с эталоном. Правки пользователя живут в `book` (пользовательская копия), в матчинге и поиске метаданных не участвуют.
- Обложки эталона не скачиваем массово (гигабайты): храним внешний URL, файл скачиваем в момент, когда книгу добавляют к себе — как сейчас.

### M15 — Фоновое наполнение (библиография авторов)

- Очередь: `crawl_task` (kind='author-bibliography', authorId, status, attempts, scheduledAt) + фоновый воркер в server.ts: медленный цикл с паузами и джиттером (FantLab в test-режиме — щадящий rate limit), env-флаг `CRAWL_ENABLED`.
- Триггеры: появление автора с fantlabId → задача; повторное обновление — не чаще раза в N месяцев; ручная кнопка «Обновить» на странице автора.
- Источник: FantLab `/autor/{id}` — произведения и издания; фильтруем: русскоязычные издания, базовые поля.
- UI: на странице автора секция «Другие книги автора» из эталона (с пометкой даты обновления); добавление такой книги к себе — в один тап (эталон → предзаполненный черновик формы).

### Риски и правила

- FantLab API — «test mode»: воркер обязан переживать ошибки/пустые ответы и не долбить сервис (глобальный интервал между запросами, ретраи с бэкофом).
- Дедупликация эталона между источниками — по ISBN; при конфликте приоритет FantLab (как в merge).
- Объём: у плодовитых авторов сотни изданий — лимит на задачу + только издания с ISBN.
- ИИ-механики поверх эталона (обогащение, рекомендации) — отдельный этап после M15.

## Ключевые сценарии

1. **Разбор завала.** Алексей с телефоном у стопки книг: открыл «Добавить» → выбрал библиотеку → сканирует подряд: пик — черновик — поправил полку — сохранил — «Добавить ещё». Непонятные книги падают в «Неразобранное», раскладываются по полкам позже с ноутбука.
2. **Дал почитать.** Друг уносит книгу: на карточке «Дать почитать» → имя, срок. Книга получает штамп «НА РУКАХ». Через месяц в `/loans` видно, у кого что; вернули — отметил возврат, запись ушла в историю.
3. **Гость просит книгу.** Друг открывает присланную ссылку, листает полку, жмёт «Хочу взять почитать» на детективе, пишет имя. Владелец в `/requests` одобряет — создана выдача. При встрече передаёт книгу.
4. **Серия.** Куплен третий том цикла: при добавлении по ISBN серия подтянулась сама; на странице серии видно тома 1–3 по порядку и чего не хватает (визуально, по номерам).
5. **Подарил.** Книга уехала к маме насовсем: статус «Подарена» (кому+когда) — с полки исчезла, в каталоге находится фильтром «подаренные».
6. **Семейная библиотека.** Алексей приглашает Олю инвайт-ссылкой — «Дом» теперь общий: Оля добавляет свои книги на те же полки, ставит свои оценки; выдачи и заявки видят оба; у каждого свой виш-лист и свои рецензии.

## Не в MVP (бэклог фазы 2)

- Аккаунты друзей: их оценки, комменты, рецензии, реакции.
- Импорт (CSV/Goodreads/LiveLib) и экспорт.
- FTS5-полнотекст, стемминг.
- Тёмная тема (токены готовы к ней).
- Service worker / офлайн (в MVP только manifest).
- Capacitor-обёртки для сторов.
- Подборки: собственные кураторские списки книг (отдельный функционал; место им скорее в Каталоге).
- Напоминания о сроках возврата.
- Штрихкод-этикетки для своих книг.

## Критерий готовности MVP

Сквозной сценарий на проде с телефона: регистрация → библиотека + полки → отсканировать стопку → разложить «Неразобранное» → оценка + рецензия → «дал почитать» → share-ссылка другу → заявка «хочу почитать» → одобрение → возврат. Плюс: патина/акценты полок работают, поиск по-русски работает, рестарт контейнера ничего не теряет.
