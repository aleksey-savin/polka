# Polka — гайдлайн по TypeScript

Основа: статья [«TypeScript Best Practices in 2025»](https://dev.to/mitu_mariam/typescript-best-practices-in-2025-57hb) (dev.to, Mitu Mariam), адаптирована под стек проекта (Bun + TanStack Start + Vite). Пункты статьи про Angular, Nx, TensorFlow.js и Webpack к проекту не применимы и опущены осознанно.

## Правила из статьи (адаптированные)

1. **Явные типы вместо `any`.** `any` запрещён (ESLint это следит). Публичные функции сервисов и серверных функций объявляют типы параметров и возврата явно; внутри функций полагаемся на вывод типов.

2. **`unknown` вместо `any`** для данных неизвестной формы (ответы внешних API метаданных, JSON из кэша). Сужение — через type guard'ы/`typeof` или разбор `zod`-схемой: внешние данные попадают в домен только через `schema.parse()`.

3. **Строгий режим.** В `tsconfig.json`: `"strict": true` (включает `strictNullChecks` и остальное). Ослаблять флаги нельзя.

4. **Доверяй выводу типов.** Не аннотируй то, что TypeScript выводит сам (`const books = await listBooks()` — тип придёт из сигнатуры). Аннотации — на границах: параметры, возвраты публичных API, пустые структуры (`const drafts: BookDraft[] = []`).

5. **`const` по умолчанию + `as const`** для фиксированных наборов: списки статусов, пресеты цветов полок, приоритеты источников метаданных — `const READING_STATUSES = ['unread', 'reading', 'read', 'abandoned'] as const` и производный тип `typeof READING_STATUSES[number]`.

6. **Mapped types** — чтобы производить типы, а не дублировать их: `Partial<BookDraft>` для результатов одного источника метаданных, `Pick`/`Omit` для публичных DTO share-витрины (белый список полей).

7. **Template literal types** — точечно, где строки структурированы (например, ключи CSS-переменных темы `--shelf-${string}`). Не превращать в самоцель.

8. **Conditional types** — только в утилитах общего назначения, если без них реально хуже. В прикладном коде предпочитаем простые типы.

9. **Динамические импорты** для тяжёлого и редко нужного: `barcode-detector`/zxing-wasm грузится `await import(...)` при открытии сканера, не в основном бандле.

10. **Code splitting** — TanStack Start/Vite делит бандл по роутам автоматически; не ломать это (не тянуть тяжёлые модули в общие layout'ы).

11. **Типизация React-компонентов.** Пропсы — именованный `type XxxProps`; компоненты — обычные функции с типизированными пропсами (`function BookCard({ book }: BookCardProps)`). `React.FC` не используем — в актуальном React он ничего не добавляет.

12. **ESLint + Prettier**: `typescript-eslint` (flat config, `strictTypeChecked` + `stylisticTypeChecked`) + Prettier. Проверка в CI: `bun run lint && bun run format:check && tsc --noEmit`.

13. **Типы — часть каждого изменения.** Новая функциональность приходит с типами; правки схемы БД начинаются с типов Drizzle-схемы, от которой типы запросов выводятся (`$inferSelect`/`$inferInsert`). Генерируемая документация (TypeDoc) в MVP не нужна — публичного API нет; JSDoc-комментарии пишем только там, где сигнатура не самоочевидна.

## Проектные правила (сверх статьи)

14. **Без `verbatimModuleSyntax`** — прямое предупреждение документации TanStack Start: с ним серверный код может утечь в клиентский бандл.

15. **Логика — в `services/`, чистой и типизированной.** `createServerFn`-обёртки тонкие: middleware (сессия) → `zod`-валидатор → вызов сервиса. Обёртки не тестируются напрямую, сервисы — тестируются `bun test`.

16. **Границы данных = zod.** Всё, что пришло снаружи (формы, query, ответы внешних API, FormData), проходит схему; внутренние вызовы между сервисами схемами не дублируем — там работает система типов.

17. **Точная пиновка версий** (без `^`): TanStack Start в RC, у better-auth близка 1.7 — переименования API уже случались. Бамп зависимостей — отдельным осознанным коммитом с чтением ченджлога.

18. **Литеральные union-типы вместо enum** (`status: 'in_library' | 'wishlist' | 'gifted' | 'lost'`): дружат с Drizzle (`text({ enum: [...] })`), zod и выводом типов; `enum` в проекте не используем.
